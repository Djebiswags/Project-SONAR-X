## 2025-08-05 - CustomTkinter Keyboard Accessibility and Resource Cleanup
**Learning:** In CustomTkinter or Tkinter applications, visual elements often dynamically schedule recurring UI/telemetry updates using `.after()`. To prevent memory leaks, background processing overhead, or Tcl threading exceptions when destroying these UI structures, it's critical to track the scheduled job ID and call `after_cancel()` inside an overridden `destroy()` method. Additionally, to ensure a smooth keyboard-centric navigation and accessibility flow (such as closing utility windows with the Escape key), binding globally using `bind_all()` rather than on the widget level ensures keys are caught regardless of which component holds focus.
**Action:** When creating CustomTkinter overlays or telemetry HUDs, store `.after()` handle IDs, cancel them on window teardown, and use `bind_all("<Escape>", ...)` to allow keyboard accessibility.
